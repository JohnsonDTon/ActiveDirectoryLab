Microsoft has a ASR Rules reference list to enforce. Eventually for an actual enterprise, you'd want to enforce all of them <br>
However, some of these rules may break how your software functions in your environment, so proper testing is needed <br>
Unfortunately were simulating a enterprise lab, but lab is a lab in the end. So I will implement standard protections that Microsoft recommends first. <br> <br>
```text
Block credential stealing from LSASS
Block abuse of exploited vulnerable signed drivers
Block persistence through WMI event subscription
```

Create GPO and link to OU
```powershell
New-GPO -Name "Workstations - Defender ASR"

New-GPLink `
    -Name "Workstations - Defender ASR" `
    -Target "OU=Workstations,DC=adlab,DC=test"
```

Enable Defender ASR. Other commands/rules dont work if this is not value=1
```powershell
Set-GPRegistryValue `
    -Name "Workstations - Defender ASR" `
    -Key "HKLM\SOFTWARE\Policies\Microsoft\Windows Defender\Windows Defender Exploit Guard\ASR" `
    -ValueName "ExploitGuard_ASR_Rules" `
    -Type DWord `
    -Value 1
```

Block credential stealing from LSASS (LSASS notes below)
```text
lsass.exe is the Local Security Authority Subsystem Service. It's the Windows process that handles logins, and to do that job it keeps credential material in its memory. After someone logs into a machine, LSASS can hold:

NTLM password hashes
Kerberos tickets
Sometimes plaintext passwords, depending on configuration

The attack. If an attacker gets admin rights on a workstation, they can read LSASS's memory and pull out everyone's credentials who has logged in recently. This is called credential dumping.

With a stolen hash, the attacker can do pass-the-hash and log into other machines without ever knowing the password. If a domain admin ever logged into that workstation, the attacker can go from one compromised Win11 box to owning the whole domain. That's why it's a staple of real intrusions.

What the rule does. To read another process's memory, a program first has to open a handle to it with memory-read permissions. This rule blocks untrusted processes from opening a handle to lsass.exe with those permissions. Windows itself and legitimate security software still work, because Defender doesn't block trusted system components. Everything else gets denied, so the dump attempt fails.
```
```powershell
Set-GPRegistryValue `
    -Name "Workstations - Defender ASR" `
    -Key "HKLM\SOFTWARE\Policies\Microsoft\Windows Defender\Windows Defender Exploit Guard\ASR\Rules" `
    -ValueName "9e6c4e1f-7d60-472f-ba1a-a39ef669e4b2" `
    -Type String `
    -Value "1"
```
