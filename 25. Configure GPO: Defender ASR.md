Note: In enterprises, you'd use a centralized antivirus management and not group policies for this. It's much easier to administer. <br>
I'll configure a surface level GPO for Windows Defender/ASR for now since I won't be subscribing to any paid antivirus licenses for this lab. <br>
Microsoft Defender also needs to be active mode (aka no other antivirus active) for ASR to work. <br> <br>

Microsoft has a ASR Rules reference list to enforce. Eventually for an actual enterprise, you'd want to enforce all of them <br>
However, some of these rules may break how your software functions in your environment, so proper testing is needed <br>
Unfortunately were simulating a enterprise lab, but lab is a lab in the end. So I will implement standard protections that Microsoft recommends first. <br> <br>

Create GPO and link to OU
```powershell
New-GPO -Name "Workstations - Defender ASR"

New-GPLink `
    -Name "Workstations - Defender ASR" `
    -Target "OU=Workstations,DC=adlab,DC=test"
```

Enable Defender ASR. Other commands/rules dont work if this is not value=1
```powershell
Set-GPRegistryValue `
    -Name "Workstations - Defender ASR" `
    -Key "HKLM\SOFTWARE\Policies\Microsoft\Windows Defender\Windows Defender Exploit Guard\ASR" `
    -ValueName "ExploitGuard_ASR_Rules" `
    -Type DWord `
    -Value 1
```

Block credential stealing from LSASS <br>
lsass.exe is the Windows process that handles login, and it stores credential in its memory. Attackers who gain admin rights can read LSASS's memory and pull out credentials that were logged in recently. We implement this rule to block untrusted processes from opening lsass.exe.
```powershell
Set-GPRegistryValue `
    -Name "Workstations - Defender ASR" `
    -Key "HKLM\SOFTWARE\Policies\Microsoft\Windows Defender\Windows Defender Exploit Guard\ASR\Rules" `
    -ValueName "9e6c4e1f-7d60-472f-ba1a-a39ef669e4b2" `
    -Type String `
    -Value "1"
```

Block abuse of exploited vulnerable signed drivers <br>
This blocks applications from writing a known-vulnerable signed driver to disk. Defender checks against a list of drivers Microsoft has identified as abused in the wild, so it's a targeted block rather than a general one. A security-flawed signed (aka deemed legitimate) driver is installed (with admin rights) and this flaw allows attacker to run code in a computer's kernel, it will have the ability to do anything. Attackers normally do this to disable antivirus before launching their ransomware attack.
```powershell
Set-GPRegistryValue `
    -Name "Workstations - Defender ASR" `
    -Key "HKLM\SOFTWARE\Policies\Microsoft\Windows Defender\Windows Defender Exploit Guard\ASR\Rules" `
    -ValueName "56a863a9-875e-4185-98a7-b882c64b5ce5" `
    -Type String `
    -Value "1"
```

Block persistence through WMI event subscription <br>
This blocks the creation of malicious WMI event subscriptions, so the persistence never gets established. Persistence means the attacker keeps access even after a reboot. <br>
WMI is a built-in Windows management framework. It lets you create subscriptions that say "when this event happens, run this action," and these are stored in the WMI repository and survive reboots. Attackers abuse this because it's a less obvious place to hide than the usual spots like Run keys and scheduled tasks. <br>
This rule only blocks new malicious subscriptions. It doesn't remove one that's already created.
```powershell
Set-GPRegistryValue `
    -Name "Workstations - Defender ASR" `
    -Key "HKLM\SOFTWARE\Policies\Microsoft\Windows Defender\Windows Defender Exploit Guard\ASR\Rules" `
    -ValueName "e6db77e5-3df2-4cf1-b95a-636979351e5b" `
    -Type String `
    -Value "1"
```
