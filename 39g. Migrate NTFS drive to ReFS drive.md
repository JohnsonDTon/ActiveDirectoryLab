My back-up volume disk on BACKUP01 is currently set up as a NTFS disk, so Fast cloning isn't active. <br>
This is a good project to do because ReFS supports block cloning, Veeam can build a “synthetic full” backup by pointing at blocks that already exist instead of copying them. A new full backup then takes almost no extra space and finishes in seconds. <br> <br>

Create new disk. Run on Hyper-V Host
```powershell
New-VHD `
    -Path "E:\ActiveDirectoryLab\BACKUP01\Backup-Repo-ReFS.vhdx" `
    -SizeBytes 300GB `
    -Dynamic
```

Add to BACKUP01.
```powershell
Add-VMHardDiskDrive `
    -VMName "BACKUP01" `
    -Path "E:\ActiveDirectoryLab\BACKUP01\Backup-Repo-ReFS.vhdx"
```

Check Disk number on BACKUP01. Run on BACKUP01
```powershell
Get-Disk |
    Where-Object PartitionStyle -eq "RAW" |
    Select-Object Number, Size
```

Initialize Disk
```powershell
Initialize-Disk `
    -Number 2 `
    -PartitionStyle GPT
```
```powershell
New-Partition `
    -DiskNumber 2 `
    -UseMaximumSize `
    -DriveLetter F
```
```powershell
Format-Volume `
    -DriveLetter F `
    -FileSystem ReFS `
    -AllocationUnitSize 65536 `
    -NewFileSystemLabel "Backup-Repo-ReFS"
```

Quiet Veeam. Make sure no jobs are going to run
```text
Veeam console -> Home -> Jobs -> Disable all three jobs (make sure none is running)
```

Stop Veeam Service
```powershell
Get-Service Veeam* |
    Stop-Service -Force
```

Create C:\Temp folder for robocopy logs
```powershell
New-Item `
    -Path "F:\Backups" `
    -ItemType Directory
```

Robocopy E Drive to F Drive
```powershell
robocopy "E:\Backups" "F:\Backups" /E /COPYALL /DCOPY:DAT /R:1 /W:1 /LOG:C:\Temp\migrate.log
```

Verify copy. Both numbers should match
```powershell
(Get-ChildItem -Path "E:\Backups" -Recurse | Measure-Object -Property Length -Sum).Sum
(Get-ChildItem -Path "F:\Backups" -Recurse | Measure-Object -Property Length -Sum).Sum
```

Swap the disk letters
```powershell
Set-Partition -DriveLetter E -NewDriveLetter G
Set-Partition -DriveLetter F -NewDriveLetter E
```

Start Veeam
```powershell
Get-Service Veeam* |
    Start-Service
```
```text
Backup Infrastructure -> Backup Repositories -> the repository -> Properties -> Next through the wizard -> Apply
Right click the repository -> Rescan
Home -> Backups -> Disk: the backups should appear
Home -> Jobs -> Enable each job -> Start one and confirm Success
Do a file restore from an existing restore point
```

Confirm Get-Volume -DriveLetter E shows ReFS and 65536. <br>
Decommission the old disk only after those checks pass. Wait a few days, then detach G: from the VM and delete its VHDX.
