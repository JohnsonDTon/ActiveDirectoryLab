Bitlocker helps encrypt your data in your hard-drive. <br>
This helps data protection in case your laptop/PC gets stolen. <br>
The stealer would need windows credential in order to access the data <br> <br>

Create GPO and link to OU. Run on DC
```powershell
New-GPO -Name "Workstations - BitLocker"

New-GPLink `
    -Name "Workstations - BitLocker" `
    -Target "OU=Workstations,DC=adlab,DC=test"
```

Enable OS Recovery
```powershell
Set-GPRegistryValue `
    -Name "Workstations - BitLocker" `
    -Key "HKLM\SOFTWARE\Policies\Microsoft\FVE" `
    -ValueName "OSRecovery" `
    -Type DWord `
    -Value 1
```

Configure to require recovery password for BitLocker-protected operating system drives
```powershell
Set-GPRegistryValue `
    -Name "Workstations - BitLocker" `
    -Key "HKLM\SOFTWARE\Policies\Microsoft\FVE" `
    -ValueName "OSRecoveryPassword" `
    -Type DWord `
    -Value 1
```

Configure to require recovery key for BitLocker-protected operating system drives
```powershell
Set-GPRegistryValue `
    -Name "Workstations - BitLocker" `
    -Key "HKLM\SOFTWARE\Policies\Microsoft\FVE" `
    -ValueName "OSRecoveryKey" `
    -Type DWord `
    -Value 1
```

Configure the AD DS Backup <br>
This stores the recovery password and key-package in the on-prem AD.
```powershell
Set-GPRegistryValue `
    -Name "Workstations - BitLocker" `
    -Key "HKLM\SOFTWARE\Policies\Microsoft\FVE" `
    -ValueName "OSActiveDirectoryBackup" `
    -Type DWord `
    -Value 1
```
```powershell
Set-GPRegistryValue `
    -Name "Workstations - BitLocker" `
    -Key "HKLM\SOFTWARE\Policies\Microsoft\FVE" `
    -ValueName "OSActiveDirectoryInfoToStore" `
    -Type DWord `
    -Value 1
```

Require AD Backup before Bitlocker encryption <br>
Wouldn't want devices encrypted without having the key, right?
```powershell
Set-GPRegistryValue `
    -Name "Workstations - BitLocker" `
    -Key "HKLM\SOFTWARE\Policies\Microsoft\FVE" `
    -ValueName "OSRequireActiveDirectoryBackup" `
    -Type DWord `
    -Value 1
```

Require your client devices to have TPM to startup <br>
TPM provides hardware-backed protection for BitLocker's key material and can release the protected key only when the expected boot environment is present.
```powershell
Set-GPRegistryValue `
    -Name "Workstations - BitLocker" `
    -Key "HKLM\SOFTWARE\Policies\Microsoft\FVE" `
    -ValueName "UseAdvancedStartup" `
    -Type DWord `
    -Value 1
```

Verify
```powershell
Get-GPO `
    -Name "Workstations - BitLocker" |
    Get-GPOReport `
    -ReportType Html `
    -Path "C:\Temp\Workstations-BitLocker.html"

Start-Process "C:\Temp\Workstations-BitLocker.html"
```

Verify on Client

```powershell
gpupdate /force
```
```powershell

```
More verification. We want TpmPresent : True and TpmReady   : True
```powershell
Get-Tpm
```

Enable Bitlocker with XTS-AES 256 encryption. Run this on CLIENT machines. Has to be done 1 by 1. Do it during deployments moving forward.
```powershell
Enable-BitLocker `
    -MountPoint "C:" `
    -EncryptionMethod XtsAes256 `
    -UsedSpaceOnly `
    -TpmProtector
```
