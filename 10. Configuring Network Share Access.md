This assumes your Network Share is built like this on your File Server (FILE01).
```text
├── C:\                  Windows Server OS
├── D:\                  DVD Drive
└── E:\                  FileServerData
    └── Shares
        ├── IT
        ├── HR
        ├── Finance
        └── Public
```
Also assume you have this security group that been set up.
```text
ADLAB.TEST
│
└── Security Groups
    │
    ├── Global
    │   ├── GG-All-Employees
    │   ├── GG-IT-Users
    │   ├── GG-HR-Users
    │   └── GG-Finance-Users
    │
    └── Domain Local
        ├── DL-FILE01-IT-Read
        ├── DL-FILE01-IT-Modify
        ├── DL-FILE01-IT-Full
        ├── DL-FILE01-HR-Read
        ├── DL-FILE01-HR-Modify
        ├── DL-FILE01-HR-Full
        ├── DL-FILE01-Finance-Read
        ├── DL-FILE01-Finance-Modify
        ├── DL-FILE01-Finance-Full
        ├── DL-FILE01-Public-Read
        ├── DL-FILE01-Public-Modify
        └── DL-FILE01-Public-Full
```
Our main goal is have this kind of access structure
```text
E:\Shares\IT
    ├── Administrators      Full Control
    ├── SYSTEM              Full Control
    └── DL-FILE01-IT-Modify Modify

E:\Shares\HR
    ├── Administrators      Full Control
    ├── SYSTEM              Full Control
    └── DL-FILE01-HR-Modify Modify

E:\Shares\Finance
    ├── Administrators      Full Control
    ├── SYSTEM              Full Control
    └── DL-FILE01-Finance-Modify Modify

E:\Shares\Public
    ├── Administrators      Full Control
    ├── SYSTEM              Full Control
    └── DL-FILE01-Public-Read Read
```
<br><br>

First, verify what it's set up as. 
```powershell
Get-Acl "E:\Shares" |
    Select-Object -ExpandProperty Access

Get-Acl "E:\Shares\IT" |
    Select-Object -ExpandProperty Access

Get-Acl "E:\Shares\HR" |
    Select-Object -ExpandProperty Access

Get-Acl "E:\Shares\Finance" |
    Select-Object -ExpandProperty Access

Get-Acl "E:\Shares\Public" |
    Select-Object -ExpandProperty Access
```

You'll see something like below. We don't want this or it defeats the purpose.
```text
FileSystemRights  : ReadAndExecute, Synchronize
AccessControlType : Allow
IdentityReference : BUILTIN\Users
IsInherited       : True
InheritanceFlags  : ContainerInherit, ObjectInherit
```

Can also verify this more clean.
```powershell
Get-Acl "E:\" |
    Select-Object -ExpandProperty Access |
    Format-Table IdentityReference, FileSystemRights, AccessControlType, IsInherited, InheritanceFlags, PropagationFlags -AutoSize
```

Now to start, back up the current ACLs. <br>
Create E:\Temp folder to store backup.
```powershell
New-Item -Path "E:\Temp" -ItemType Directory -Force
```

Store current ACLs
```powershell
Get-Acl "E:\Shares" | Format-List |
    Out-File "E:\Temp\Shares-ACL-Before.txt"

Get-Acl "E:\Shares\IT" | Format-List |
    Out-File "E:\Temp\IT-ACL-Before.txt"

Get-Acl "E:\Shares\HR" | Format-List |
    Out-File "E:\Temp\HR-ACL-Before.txt"

Get-Acl "E:\Shares\Finance" | Format-List |
    Out-File "E:\Temp\Finance-ACL-Before.txt"

Get-Acl "E:\Shares\Public" | Format-List |
    Out-File "E:\Temp\Public-ACL-Before.txt"
```

Disable Inheritance on the department folders. <br>
This does not modify E:\ or E:\Shares
```powershell
$Folders = @(
    "E:\Shares\IT",
    "E:\Shares\HR",
    "E:\Shares\Finance",
    "E:\Shares\Public"
)

foreach ($Folder in $Folders) {
    $Acl = Get-Acl $Folder
    $Acl.SetAccessRuleProtection($true, $false)
    Set-Acl -Path $Folder -AclObject $Acl
}
```

Verify inheritance. We want to see 'true' <br>
Can run for other department folders too if you wish
```powershell
Get-Acl "E:\Shares\IT" |
    Select-Object Path, AreAccessRulesProtected
}
```

Verify Access now. Only admin will have access since inheritance is disabled <br>
Can run for other department folders too if you wish
```powershell
Get-Acl "E:\Shares\IT" |
    Select-Object -ExpandProperty Access |
    Format-Table IdentityReference, FileSystemRights, AccessControlType, IsInherited, InheritanceFlags, PropagationFlags -AutoSize
```
