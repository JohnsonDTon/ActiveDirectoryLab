Service Accounts (for Veeam backup for example) may have too much power, this GPO limits it <br>
Thi works in conjunction with Set up Backup server (BACKUP01).md and Configure GPO: Backup Access.md
<br> <br>


Create GPO and link to OUs
```powershell
New-GPO `
    -Name "Service Accounts - Deny Logon" `

New-GPLink `
    -Name "Service Accounts - Deny Logon" `
    -Target "OU=Servers,DC=adlab,DC=test" `
    -LinkEnabled Yes

New-GPLink `
    -Name "Service Accounts - Deny Logon" `
    -Target "OU=Domain Controllers,DC=adlab,DC=test" `
    -LinkEnabled Yes
```

Set up Log on restrictions for the groups
```text
Group Policy Management -> Group Policy Objects -> Service Accounts - Deny Logon -> right click -> Edit
Computer Configuration -> Policies -> Windows Settings -> Security Settings -> Local Policies -> User Rights Assignment

Deny log on locally
    Define these policy settings
    Add User or Group... -> ADLAB\svc-backup-srv
    Add User or Group... -> ADLAB\svc-backup-dc
    OK

Deny log on through Remote Desktop Services
    Define these policy settings
    Add User or Group... -> ADLAB\svc-backup-srv
    Add User or Group... -> ADLAB\svc-backup-dc
    OK
```
Don’t touch “Deny access to this computer from the network”, “Deny log on as a batch job” or “Deny log on as a service”. Blocking any of those would break Veeam.

Verify on DC01 and member server (like FILE01) <br>
Make C:\Temp folder if needed.
```powershell
gpupdate /force
```
```powershell
secedit /export /cfg C:\Temp\secpol.txt
```
